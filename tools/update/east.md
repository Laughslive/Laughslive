TICKETMASTER FEED: A GitHub Action (.github/workflows/ticketmaster.yml) runs every morning on its own: it fetches Ticketmaster's stand-up listings for all 34 cities into data/ticketmaster.json, merges them into index.html with tools/merge_ticketmaster.py, rebuilds the city pages and publishes. You do NOT need to research Ticketmaster shows; focus on clubs and venues that sell elsewhere. You'll re-run the merge in step 4 so the merged block is current.

FETCHING TIPS (learned the hard way):
- WebFetch only opens URLs that appeared in a WebSearch result, in an earlier fetched page, or in this prompt. So: fetch a venue's listing page first, then fetch individual event links that appear on it. If a URL is refused, run a WebSearch that surfaces it (e.g. "<venue> <month> 2026 events") and fetch the result link. Don't use curl or the shell browser — the shell can't reach outside websites (git to GitHub does work).
- Many calendars load by script and show only "Loading…". Look for a plain list view instead: a "/events/list/" page, a "?type=listing&widget=1" venue page, the venue's seatengine site (<venue>-com.seatengine.com/events), its Tixr group page, or its Etix links. Multi-night runs often list no times on the overview page; open that event's own page (e.g. seatengine /events/<id>, thewilbur.com/event/<slug>/, tixr event pages) to get each showtime.
- When a page lists two times per show without labels (e.g. The Port), the earlier is doors and the later is the show time. Always use show time, not doors.
- Prefer the exact per-show ticket URL; otherwise the venue's calendar URL.
- Don't print or Read the whole of index.html (it's ~500 KB); edit it with small Python scripts that search for exact strings.
